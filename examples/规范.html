2. 命名规范

好命名应「一致 + 信息丰富」：同样含义在不同文件/路由/Prop 间保持一致；用词无二义性。

2.1 命名分类

  • camelCase （小驼峰）： userInfo
  • PascalCase （大驼峰）： UserInfo
  • kebab-case （短横线）： user-info
  • snake_case （下划线）： user_info
  • UPPER_SNAKE_CASE （常量）： MAX_RETRY_COUNT

2.2 场景

大驼峰（PascalCase）

  • Vue 组件文件名与其默认导出保持一致，如 CoolComponent.vue 。
  • template 中使用组件也用 PascalCase：

<CoolComponent />

    <cool-component />
</template>
<script setup lang="ts">
import CoolComponent from "./CoolComponent.vue";
</script>

<template> <!-- ✓ GOOD --> <!-- ✗ BAD -->

例外：eggjs 中 controller/service 虽为 Class，但使用时是实例化对象，用

ctx.service.dataMid.getData() ，对应文件名 dataMid.ts 。 小驼峰（camelCase）

  • 变量、普通函数、TS 文件（ financial.ts 、 request.ts ）、类型文件（ fund.ts ）。

短横线（kebab-case）

  1. 页面目录、路由 path、路由 name：如 fund-detail/ 、 path: '/fund-detail' 、 name: 'fund-detail' 。

2. 非 JS/TS 资源与类名：静态资源（字体/css/scss/html）、HTML 属性、CSS class 名。

依据 SEO 实践：URL 中 - 被搜索引擎当作空格，利于分词检索； _ （如 tars 协议）会被忽略。故路由与页面目录用短横线。

  1. 自定义事件名：

<button @click="$emit('my-event')" />

    <button @click="$emit('myEvent')" />
</template>

<template> <!-- ✓ GOOD --> <!-- ✗ BAD --> ⚠️ 与旧规范的衔接：旧规范「页面级组件、路由名都用短横线」指路由与目录，不是 .vue 文件名。组件文件仍用 PascalCase，目录/路由用 kebab-case，二者不冲突。 下划线（snake_case） 仅用于「需与后端协议/数据库保持一致」处：如 tars 协议接口、DB 列名（ user_name ）。 常量 UPPER_SNAKE_CASE ： API_BASE_URL 、 MAX_AMOUNT 。

2.3 单复数【建议】

文件名用单数；目录下所有子元素平行且为同类时用复数目录名（如 components/ 、 pages/ ），否则用单数。

2.4 函数 / 方法命名

  • 普通函数： 动词 + 名词 ，如 getList 、 formatAmount 、 fetchTradeInfo 。
  • 事件处理函数：统一 handle 前缀（⚠️ 旧规范的 onXxx 为 Options API 遗留写法，新版统一用

handle ）：

 const handleSubmit = () => { /* ... */ };
const handleTabChange = (tab: string) => { /* ... */ };

常用动词表（节选，保持旧规范）：等。 get/set 、 add/remove 、 create/destroy 、 load/save 、 open/close 、 find/search 、 update/re

  • 页面跳转函数： goTo 前缀，如 goToDetail(id) 、 goToTrade() 。
  • 布尔值： is / has / can 前缀，如 isLoading 、 hasPosition 、 canSubmit 。

3.1 统一响应结构（⚠️ 高频出错点）

❌ 错误✅ 正确说明
{ result: [...] }{ data: [...] }字段固定为 data
{ status: 'ok' }{ ret: 0 }状态字段固定为 ret
{ code: 0 }{ ret: 0 }同上
裸数组 [...]{ ret: 0, data: [...], msg: '' }不能裸返回
 interface ApiResponse<T> {
     data: T; // 业务数据（泛型）
     msg: string; // 提示信息
 }
 { status: 'ok' } { ret: 0 } 状态字段固定为 ret
裸数组 [...] { ret: 0, data: [...], msg: '' } 不能裸返回
 { ret: 0, data: [...], msg: 'success' } // 列表成功
{ ret: 0, data: {...}, msg: 'success' } // 详情成功
{ ret: 0, data: null, msg: '操作成功' } // 写操作成功
{ ret: 1, data: null, msg: '数据不存在' } // 失败

场景写法： ⚠️ 待团队对齐的冲突：后端 web/coding-standards.md 约定为 { code, message, data } ，与前端 { ret, data, msg } 不一致。建议二选一（推荐前端 ret/data/msg 作为契约），或在 request 封装层做一次字段适配，避免散落在业务代码里。

5. Vue 编码规范

5.1 <script setup> 推荐结构顺序

 <script setup lang="ts">
// 1. 导入
import { computed, onMounted, ref } from 'vue';
import { CardSection, PageHeader } from '@/components';
// 2. 类型定义
interface FundItem { id: string; name: string; }
// 3. props / emits（类型化）
const props = defineProps<{ title: string }>();
const emit = defineEmits<{ submit: [] }>();
// 4. 响应式状态
const loading = ref(false);
const list = ref<FundItem[]>([]);
// 5. 计算属性
const total = computed(() => list.value.length);
// 6. 方法
const handleSubmit = () => emit('submit');
// 7. 生命周期
onMounted(() => { /* init */ });
</script>

旧规范 defineProps({ title: String }) 写法仍可用，但推荐上面的类型化写法以获得完整类型推导。

5.2 Props / Emits 类型化

 const props = defineProps<{ title: string; count: number; disabled?: boolean }>();
const emit = defineEmits<{ update: [value: number]; delete: [id: number] }>();

5.3 ref vs reactive

// const userName = ref(''); const userAge = ref(0); // ✗ 过度使用 ref
  • 基础类型、单字段用 ref 。

5.4 组件复用（来自 prd-to-ui）

  • 优先用已有组件，禁止重复开发；统一从 @/components 导入。
  • 不要发明不存在的组件名，缺组件先判断能否用现有组件组合解决。

6. 样式规范

6.1 CSS 命名

  • 公共组件：用 BEM，且不加 scoped （便于使用方覆盖样式），Block 加前缀避免冲突（如 el- 、 van- ）。

Block__Element--Modifier → menu-fixed__cell--active

  • 页面 scoped 样式：用 kebab-case，命名可简短。

6.2 设计系统（引用 prd-to-ui）

 $color-bg-primary: #f7f8fa; // 页面主背景（非纯白）
$color-text-primary: #1a1a2e; // 主文字（非纯黑）
$color-brand: #4f6ef7; // 品牌色（按项目自定义）
$shadow-card: 0 1px 3px rgba(0,0,0,.04), 0 1px 2px rgba(0,0,0,.02);
$radius-lg: 14px;
// 间距以 8px 为基准：4/8/12/16/20/24/32/40/48

关键 tokens（移动端/H5 为主，Web 端可调整）：

  • 页面背景用 #f7f8fa ，主文字用 #1a1a2e （不要用纯黑纯白）。
  • 卡片：轻边框 + 柔和阴影，圆角统一，卡片间距 20px 左右节奏。
  • 渐变 Header 尾部保持足够深，保证白字可读（不要过渡到白色）。
  • 同页面字号层级不超过 3 种。

完整色彩/排版/间距/按钮系统见 prd-to-ui/SKILL.md 的「视觉设计系统」章节。

6.3 750 设计稿 rem 转换

.page-title { font-size: 36px; } // 自动转 → 375 屏约 18px

按 750px 设计稿写原始 px， postcss-pxtorem 自动转 rem（1rem = 75px）：

  • 水平相关（ width / font-size /左右 padding / margin / border-radius ）写 px 自动转；
  • 垂直相关（ height / line-height /上下 margin 、 gap ）保持 px 固定。

6.4 z-index 堆叠规范

按「内容层 → 结构层 → 互动层」分层，各层 z-index 控制在规范区间内，避免全局数值打架：

  1. 内容层 0 ~ 10
  2. 结构层：底部 30~40 、中下部 40~50 、顶部 50~60
  3. 互动层中部 70~80

7. 编码建议

  1. 单文件建议不超过 250 行（约 5 屏），超 500 行必须拆分模块。
  2. try/catch/finally 按需使用：catch、finally 可选，但 try 至少配其一。
  3. Service 入参用对象（见 3.2）。
  4. 复杂或非直观的变量需注释说明用途与来源；不必逐行注释。
  5. 新注册公共组件先评审是否纳入公共引用（现有公认公共组件：Toast、Dialog、Cell，其余按需引用）。

8. Commit 消息规范

采用 Angular 规范（与 prd-to-ui 一致）： <type>(<scope>): <subject> <body> <footer>

 git commit -m "fix: 修复点击事件偶尔未触发的bug"
git commit -m "docs(changelog): update changelog to beta.5"
  • type： feat / fix / docs / style / refactor / perf / test / chore / revert
  • scope（可选）：影响范围
  • subject：简短必填
  • footer： BREAKING CHANGE 或 Closes #25

撤销提交以 revert: 开头，body 固定写 This reverts commit {hash}. 。 配套工具： @commitlint/cli + @commitlint/config-conventional + husky + commitizen （ cz-customizable ）+ standard-version （自动 changelog / 升版 / 打 tag）。配置参见旧规范「工具」章节及 prd-to-ui 的提交规范。

9. 微信小程序规范

小程序（原生 / Taro / uni-app）与 Web/Vue 多数规范一致，本节只标出差异点与平台特有约束。若用 Taro/uni-app（Vue 语法写小程序），则第 2~8 节 Vue 规则基本直接适用。

9.2 命名

  • 页面目录：kebab-case（与 Web 路由目录一致）。
  • 自定义组件：
  • 原生小程序：文件名推荐 kebab-case（WXML 标签对大小写不敏感， <my-card> 更稳），json 中

usingComponents 注册后模板使用同名 kebab 标签。

  • Taro/uni-app（Vue 语法）：仍用 PascalCase（ MyCard.vue ），与本规范第 2.2 节一致。
  • 事件处理函数：仍用 handle 前缀（如 handleTap ），通过 bindtap="handleTap" 绑定。
  • 生命周期用 on 前缀： onLoad / onShow / onReady / onHide / onUnload ——

这是小程序平台保留钩子，与「事件函数用 handle 前缀」不冲突（ on 表生命周期， handle 表自定义事件）。

9.3 单位（rpx）

 /* 小程序 wxss，按 750 设计稿写 */
.page-card { width: 690rpx; padding: 24rpx 30rpx; border-radius: 20rpx; border: 1px solid #e5e7eb; }
  • 小程序用 rpx，规定 750rpx = 屏幕宽度 ，按 750 设计稿直接写 rpx（与 H5 的 750 设计稿基准一致，但 H5 写 px 由 postcss 转 rem，小程序直接写 rpx）。
  • 1px 物理边框、阴影等仍用 px ，避免 rpx 在异形屏被缩放。

9.6 路由与分包

  • 页面需在 app.json 的 pages 中注册，路由由框架管理， wx.navigateTo 跳转。
  • 页面栈上限 10 层：深链路用 wx.redirectTo / wx.reLaunch 替换栈，避免 navigateTo 叠加超限。
  • 分包加载：主包 ≤ 2MB、总包 ≤ 20MB；非首屏模块放 subpackages ，按需加载。

9.7 接口与 TS

  • 接口响应同样统一 { ret, data, msg } （见第 3.1 节），业务数据从 res.data 取。
  • 用 miniprogram-api-typings 获得 API 类型；业务类型定义复用 src/types ，与 Web 共享。
  • wx.request 统一封装为 request<T> ，避免散落回调。

12. 前端常用名词

团队前端开发高频术语速查。命名风格类名词请同时参阅本文第 2 节。

基础概念

  • report 上报：将前端埋点、异常、性能等数据发送到服务端统计系统的行为。
  • SPA（Single Page Application）：单页应用，整站由一个 HTML 承载，路由切换靠 JS

局部刷新，不整页刷新。

  • SSR（Server Side Rendering）：服务端渲染，首屏由服务端生成 HTML，利于 SEO 与首屏速度。
  • CSR（Client Side Rendering）：客户端渲染，首屏由浏览器 JS 渲染。
  • PWA（Progressive Web App）：渐进式 Web 应用，具备离线、可安装、消息推送等类原生能力。
  • HMR（Hot Module Replacement）：模块热替换，改动代码后局部刷新，不丢失页面状态。
  • VDOM（Virtual DOM）：虚拟 DOM，用 JS 对象描述真实 DOM，diff 后最小化更新。
  • hydration（注水/激活）：SSR 把静态 HTML 交给客户端后，Vue/React 接管事件绑定的过程。

onXxx

框架与 Vue 生态

  • SFC（Single File Component）：单文件组件，即 .vue 文件（template + script + style 一体）。
  • Composition API：Vue 3 组合式 API，以 setup / <script setup> 组织逻辑。
  • Options API：Vue 2 风格，按 data / methods / computed 等选项组织。
  • ref：组合式 API 中包裹基础类型/对象的响应式引用，取值用 .value 。
  • reactive：将对象变成深响应式代理。
  • computed：依赖变化自动重算的派生状态（带缓存）。
  • watch / watchEffect：侦听响应式数据变化执行副作用。
  • Prop：父组件向子组件传递的数据，子组件只读。
  • Emit：子组件向父组件回传事件。
  • Slot（插槽）：组件预留的内容分发占位，支持默认/具名/作用域插槽。
  • Teleport：把内容渲染到 DOM 其他位置（如弹窗挂到 body）。
  • Pinia / Vuex：Vue 状态管理库（Vue 3 推荐 Pinia）。
  • Router / Route： Router 是路由实例， Route 是当前路由信息。
  • Meta：路由元信息，如 { title, showTab } ，用于控制页面级行为。
  • Volar（Vue Language Tools）：Vue 3 官方语言服务插件（替代已停更的 Vetur）。

工程化与构建

  • Vite：基于原生 ESM 的新一代构建/开发工具，启动快、HMR 快。
  • Webpack / Rollup：打包工具，负责模块打包与产物优化。
  • Bundle / Chunk： Bundle 是最终产物文件， Chunk 是打包过程中的代码块（如路由懒加载拆出的分包）。
  • Tree Shaking：剔除未使用代码，减小体积。
  • Code Splitting（代码分割）：按路由/组件把代码拆成多个 chunk，按需加载。
  • Lazy Loading（懒加载）：组件/图片等用到时才加载。
  • Polyfill：为旧浏览器补齐缺失的新 API。
  • ESLint：JS/TS 静态检查工具，管语法与逻辑规范。
  • Prettier：代码格式化工具，管代码样式（与 ESLint 配合时以 prettier 配置关闭冲突规则）。
  • TypeScript（TS）：带类型的 JS 超集，编译期发现错误。
  • tsc / vue-tsc：TS 类型检查器； vue-tsc --noEmit 用于 Vue 项目的类型检查（交付门禁）。
  • EditorConfig：跨编辑器统一基础格式（缩进、换行、编码）。

TypeScript 类型

  • Interface（接口）：定义对象结构，可被类实现、可合并声明。
  • Type Alias（类型别名）：用 type 定义联合/交叉/复杂类型。
  • Generic（泛型）：如 ApiResponse<T> ，让类型参数化复用。
  • Enum（枚举）：一组具名常量。
  • Union Type（联合类型）： 'a' | 'b' ，限定取值集合。

• Async/Await：基于 Promise 的异步语法糖。

  • Nullable： T | null | undefined ，可能为空的类型。
  • Optional（可选）： prop? 表示可选属性。
  • Decorator（装饰器）：以 @ 注解类/方法（后端 Midway 常用，前端较少）。

样式与视觉

  • BEM：Block__Element--Modifier 命名法，用于公共组件避免样式冲突。
  • Scoped CSS：组件样式仅作用于当前组件（页面级样式常用）。
  • rem / em / vw / vh / px：长度单位；本项目按 750 设计稿 写 px，由 postcss-pxtorem 自动转 rem。
  • Flex / Grid：弹性盒 / 网格布局。
  • Design Token：设计变量（颜色/间距/圆角/阴影），如 #f7f8fa 、 8px 间距系统。
  • z-index：层级堆叠顺序，按内容层/结构层/互动层分段取值（见本文第 6.4 节）。
  • Sticky（吸顶/吸底）： position: sticky ，如提交按钮 StickyFooter 。
  • TabBar：底部导航栏，由 route.meta.showTab 控制显隐。

组件与状态（来自 prd-to-ui 组件库）

  • PageHeader：页面头部/首屏摘要，支持 compact/default/hero 变体。
  • CardSection：卡片区块容器。
  • StatsCard：统计指标卡。
  • InfoGrid：多列信息网格。
  • StockRow / DataTable：列表行 / 数据表格。
  • BaseChart：图表组件。
  • Skeleton（骨架屏）：加载态占位。
  • EmptyPanel（空状态）：无数据时的友好提示。
  • ResultPanel（结果反馈）：提交/操作后的结果态。
  • Toast / Dialog / Modal：轻提示 / 对话框 / 模态框。
  • Badge：角标。

网络与数据

• REST / RESTful：基于资源与 HTTP 动词（GET/POST/PUT/DELETE）的接口风格。

• CRUD：增删改查（Create/Read/Update/Delete）。

  • API（Application Programming Interface）：前后端约定的接口。
  • GraphQL：一种查询语言，前端按需取字段。
  • DTO（Data Transfer Object）：接口入参/出参的数据结构。
  • VO（View Object）/ PO（Persistent Object）/ Entity：视图对象 / 持久化对象 / 实体模型。
  • Request / Response：请求 / 响应。
  • Payload：请求体数据。
  • Pagination（分页）： page / pageSize / total 列表分页。
  • Cursor（游标）：基于上一页末条的位置分页（常用于无限滚动）。
  • Mock：前端模拟接口数据（H5 项目直接写在 src/service/*.ts ）。
  • Axios / request：HTTP 客户端封装，本项目统一封装为 request<T> 。
  • Interceptor（拦截器）：统一处理请求头、登录态、响应错误。
  • 响应三字段：本项目统一 { ret, data, msg } （ ret =状态码， data =业务数据， msg =提示）。⚠️ 注意与后端 { code, message, data } 的字段差异。

微信小程序

  • 小程序（微信小程序）：运行在微信内的轻应用，无需安装、用完即走。
  • WXML：微信模板语言（类 HTML），数据绑定用 {{ }} 。
  • WXSS：微信样式语言（类 CSS），支持 rpx 单位。
  • rpx（响应式像素）： 750rpx = 屏幕宽度 ，按 750 设计稿直接书写（与 H5 的 750 设计稿基准一致，但 H5 写 px 由 postcss 转 rem，小程序直接写 rpx）。
  • setData：小程序更新视图的唯一方式，不能直接给 data 赋值。
  • 页面栈：小程序路由栈，最多 10 层（ navigateTo 叠加， redirectTo / reLaunch 替换）。
  • 分包（subpackages）：主包 ≤2MB、总包 ≤20MB，分包按需加载以控制体积。
  • AppID：小程序唯一标识，区分开发/体验/生产环境。
  • openid / unionid：用户在小程序 / 微信开放平台的唯一标识（unionid 跨应用一致）。
  • wx.login：获取登录凭证 code，换取 openid / session。
  • wx.requestPayment：调起微信支付。
  • Component：小程序自定义组件构造器（ properties / data / methods / observers / lifetimes ）。
  • usingComponents：在 .json 中注册页面/组件要使用的自定义组件。
  • Behavior：小程序代码复用混合（类似 mixin）。
  • getApp / globalData：获取小程序实例与全局数据。
  • 页面生命周期： onLoad / onShow / onReady / onHide / onUnload （ on

前缀为平台保留钩子，与事件处理函数 handle 前缀不冲突）。

  • Taro / uni-app：用 Vue / React 语法编写、可编译到小程序的跨端框架（用此类框架时，本规范的 Vue

规则基本直接适用）。

  • 原生组件命名：原生小程序推荐 kebab-case（如 <my-card> ），与 Vue PascalCase 不同；Taro/uni 仍用

PascalCase。

质量与协作

  • Lint：代码检查（ npm run lint ）。
  • Husky：Git 钩子工具，提交/推送前触发检查。
  • lint-staged：只对暂存文件做 lint/格式化，提速。
  • commitlint：校验 commit 信息格式。
  • Conventional Commits（约定式提交）：Angular 风格的 <type>(<scope>): <subject> 。
  • standard-version / Changelog：自动生成变更日志、升版本、打 tag。
  • SemVer（语义化版本）： 主.次.修订 版本号规则。
  • Code Review（代码评审）：合并前的人工/工具审查，参照本文第 10 节审查清单。
  • Unit Test / E2E：单元测试 / 端到端测试；Coverage 为测试覆盖率。
  • Snapshot（快照测试）：对渲染结果做基线比对。
